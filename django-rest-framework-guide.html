01 · Mental model

What DRF adds to Django

Django stores records in models and maps requests to views. Django REST Framework (DRF) adds tools to validate input, turn records into JSON, and build API views quickly.

HTTP request→ URL router→ ViewSet→ Serializer↔ Movie model

The response travels back as JSON. On writes, the serializer also checks the incoming data.

Model

Defines the database fields for a movie.

Serializer

Chooses API fields and validates incoming values.

ViewSet

Handles list, detail, create, update, and delete actions.

Router

Generates matching URL patterns for the viewset.

The one-sentence version: a model describes the record, a serializer describes its API representation, a viewset handles the operations, and a router gives those operations URLs.

03 · Configuration

Enable DRF and choose access rules

Add these apps to the existing INSTALLED_APPS list in config/settings.py. Keep Django's generated entries.

config/settings.py · add entries and the REST_FRAMEWORK setting

# Add these entries to the existing INSTALLED_APPS list:
"rest_framework",
"rest_framework.authtoken",
"movies",

# Add this setting elsewhere in settings.py:
REST_FRAMEWORK = {
    "DEFAULT_AUTHENTICATION_CLASSES": [
        "rest_framework.authentication.TokenAuthentication",
        "rest_framework.authentication.SessionAuthentication",
    ],
    "DEFAULT_PERMISSION_CLASSES": [
        "rest_framework.permissions.IsAuthenticatedOrReadOnly",
    ],
}

IsAuthenticatedOrReadOnly lets anyone read movies; only signed-in users can create, edit, or delete them. Token authentication is for API clients. Session authentication supports the browsable API after browser login.

Why these defaults? The source lesson uses AllowAny, which lets anonymous visitors change and delete data. This guide keeps reads public and requires authentication for writes. The token app needs a database migration, which you will run below.
Check your mental model

Question: Does enabling token authentication automatically require a token for every request?

Answer: No. Authentication identifies a user. The permission class decides which operations require that identity.

04 · Database

Create the Movie model

The model controls storage. This example keeps the fields from the Notion Movies tutorial and uses a poster URL, so no image-upload setup is needed.

movies/models.py

from django.db import models


class Movie(models.Model):
    title = models.CharField(max_length=200)
    genre = models.CharField(max_length=80)
    release_date = models.DateField()
    rating = models.PositiveSmallIntegerField()
    poster = models.URLField(blank=True, default="")

    def __str__(self):
        return self.title

Register the model if you want to add sample movies through /admin/:

movies/admin.py · optional

from django.contrib import admin
from .models import Movie

admin.site.register(Movie)
Adapt it: if your project already has a model, skip this file and use your model name and field names in the serializer and viewset.

05 · JSON and validation

Create the serializer

A serializer converts a Movie into data DRF can render as JSON. In the other direction, it checks and converts incoming JSON before a record is saved. ModelSerializer creates standard fields and create/update behavior from the model.

movies/serializers.py · create this file

from rest_framework import serializers
from .models import Movie


class MovieSerializer(serializers.ModelSerializer):
    class Meta:
        model = Movie
        fields = ["id", "title", "genre", "release_date", "rating", "poster"]
        read_only_fields = ["id"]

    def validate_rating(self, value):
        if value > 10:
            raise serializers.ValidationError("Rating must be between 0 and 10.")
        return value

The model's positive integer field rules out negative values; validate_rating sets the upper limit. DRF also checks date and URL formats. Listing fields explicitly prevents a future model field from silently appearing in the API.

Python → JSON

MovieSerializer(movie).data produces a dictionary DRF can render.

JSON → Python

is_valid() checks values and reports field errors.

06 · API behavior

Create the viewset

ModelViewSet supplies the standard CRUD actions. Tell it which records to query and which serializer to use.

movies/views.py

from rest_framework import viewsets
from .models import Movie
from .serializers import MovieSerializer


class MovieViewSet(viewsets.ModelViewSet):
    queryset = Movie.objects.all().order_by("-id")
    serializer_class = MovieSerializer

The viewset inherits the authentication and permission rules from REST_FRAMEWORK. It provides list, retrieve, create, update, partial_update, and destroy.

07 · Routing

Connect the URLs

A DefaultRouter turns the viewset's actions into collection and detail routes. The project URL file mounts them under /api/.

movies/urls.py · create this file

from django.urls import include, path
from rest_framework.routers import DefaultRouter
from .views import MovieViewSet

router = DefaultRouter()
router.register("movies", MovieViewSet)

urlpatterns = [
    path("", include(router.urls)),
]

config/urls.py · project URLs

from django.contrib import admin
from django.urls import include, path

urlpatterns = [
    path("admin/", admin.site.urls),
    path("api/", include("movies.urls")),
    path("api-auth/", include("rest_framework.urls")),
]
MethodURLAction
GET/api/movies/List movies
POST/api/movies/Create a movie
GET/api/movies/1/Read movie 1
PUT / PATCH/api/movies/1/Replace / partly update movie 1
DELETE/api/movies/1/Delete movie 1
Keep the final slash. DRF's router creates URLs such as /api/movies/ by default. /api/ is also a browsable API index.

08 · Run and verify

Try the Movies API

First make the database tables, create a user, create that user's API token, and start Django. Replace YOUR_USERNAME with the username you chose.

Terminal · run from the project folder

python manage.py makemigrations movies
python manage.py migrate
python manage.py createsuperuser
python manage.py drf_create_token YOUR_USERNAME
python manage.py runserver

Open http://127.0.0.1:8000/api/movies/ for the browsable API. An empty list is a valid first result. Sign in at /api-auth/login/ to use the HTML create form, or visit /admin/ to add a record.

Use an API client or curl

Paste the generated token in place of PASTE_TOKEN_HERE. Run one command at a time; replace 1 with the ID returned by your create request.

Terminal · example requests

# Read the collection: no token needed.
curl http://127.0.0.1:8000/api/movies/

# Create a movie.
curl -X POST http://127.0.0.1:8000/api/movies/ \
  -H "Authorization: Token PASTE_TOKEN_HERE" \
  -H "Content-Type: application/json" \
  -d '{"title":"Moonlight","genre":"Drama","release_date":"2016-10-21","rating":9,"poster":"https://example.com/poster.jpg"}'

# Change one field on movie 1.
curl -X PATCH http://127.0.0.1:8000/api/movies/1/ \
  -H "Authorization: Token PASTE_TOKEN_HERE" \
  -H "Content-Type: application/json" \
  -d '{"rating":10}'

# Delete movie 1.
curl -X DELETE http://127.0.0.1:8000/api/movies/1/ \
  -H "Authorization: Token PASTE_TOKEN_HERE"

A successful create returns 201 Created and the movie JSON. List and detail requests return 200 OK; delete returns 204 No Content. A 400 response usually identifies a field that failed validation.

Quick exercise: prove validation works

Send a movie with rating: 11. The API should return 400 Bad Request and the serializer's rating message. Then send rating: 8 and observe a successful create.

09 · Optional browser configuration

Add CORS only for a separate frontend

If a browser frontend runs at a different origin—for example, React at http://localhost:5173—the browser needs CORS response headers. You do not need CORS for curl, a same-origin Django page, or the browsable API.

Terminal · optional dependency

python -m pip install django-cors-headers

config/settings.py · add to the existing lists

# Add "corsheaders" to INSTALLED_APPS.

# Insert CorsMiddleware above CommonMiddleware in MIDDLEWARE.
# In a new Django project, this is the full default list:
MIDDLEWARE = [
    "django.middleware.security.SecurityMiddleware",
    "django.contrib.sessions.middleware.SessionMiddleware",
    "corsheaders.middleware.CorsMiddleware",
    "django.middleware.common.CommonMiddleware",
    "django.middleware.csrf.CsrfViewMiddleware",
    "django.contrib.auth.middleware.AuthenticationMiddleware",
    "django.contrib.messages.middleware.MessageMiddleware",
    "django.middleware.clickjacking.XFrameOptionsMiddleware",
]

CORS_ALLOWED_ORIGINS = ["http://localhost:5173"]
Do not open every origin by habit. The source notes use the older CORS_ORIGIN_ALLOW_ALL name. The current setting is CORS_ALLOW_ALL_ORIGINS, but a short CORS_ALLOWED_ORIGINS list is safer. CORS controls browser access; it does not replace API authentication or permissions. Cookie-based cross-origin writes also need separate CSRF configuration.

10 · Keep going

Common errors and next steps

404 at /api/movies/

Check both urls.py files, the router registration, and the final slash.

401 on POST or PATCH

Provide Authorization: Token … or log into the browsable API.

400 on POST

Read the JSON error response; check required fields, the date format, URL, and rating range.

“no such table”

Run makemigrations movies and migrate from the correct project.

Browser CORS error

Confirm the exact frontend origin and that CorsMiddleware is above CommonMiddleware.

403 with browser login

Session-authenticated unsafe requests need Django's CSRF token; use the browsable form or configure your frontend's CSRF flow.

What to remember

  1. Model: what is stored?
  2. Serializer: what enters and leaves the API, and is it valid?
  3. ViewSet: which records and actions are available?
  4. Router and URLs: where do clients send requests?
  5. Authentication and permissions: who may use each action?
