Wireframes before code: finding UX problems early

AI can generate pages quickly, but wireframes reveal whether the page order, information hierarchy, and task flow make sense.

SDGKU · Full Stack Development Immersive Capstone Studio
SDGKU FSDITopic 118.5
Why this matters

Sketching the page you can code — not the one users need

The risk

Students wireframe the page they know how to code, not the one users need.

What usually happens

Important actions get buried in menus.

The result

Navigation grows randomly as features are added.

A sketch is far cheaper to change than a generated page. Find the problem before the code.

SDGKU FSDITopic 118.5
A framework you can reuse

Five checks for every page

1

One page, one job

Many controls, one main purpose.

2

Primary action

Visually obvious, not hidden.

3

Information hierarchy

Most important info first.

4

Navigation path

Follows the user journey.

5

State variations

Empty, loading, error, success.

Using AI as a design partner, not autopilot

Let AI review the wireframe before it writes code

Good use

  • Ask AI to critique a wireframe in words before code
  • Ask for missing states: empty, loading, error, success
  • Reject a generated page that hides the main action
?

Ask AI

“Here is the page’s purpose — what is unclear or hard to find?”

SDGKU FSDITopic 118.5
Talk it through

Discussion prompts

1 Where does the visitor land first, and why?
2 What is the loudest thing on the page?
3 What would a first-time visitor do without instructions?

Studio task

Sketch, then circle the primary action

  • Sketch three key pages.
  • Circle the primary action on each.
  • Add one alternate state to one page: empty, error, or loading.
