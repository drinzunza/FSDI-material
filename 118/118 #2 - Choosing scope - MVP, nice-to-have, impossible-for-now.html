Choosing scope: MVP, nice-to-have, and impossible-for-now

Students rarely fail because the idea is too small. They fail because the first version tries to be the whole company.

SDGKU FSDITopic 118.2
Why this matters

When every feature feels equally important

The risk

Every feature feels equally important, so nothing gets prioritized.

What usually happens

AI makes advanced features look cheap, so scope grows silently.

The result

Students build impressive fragments instead of one complete workflow.

An incomplete advanced feature is worth less than a finished core workflow.

A framework you can reuse

Five layers of scope

1

Core promise

One sentence: what the app does for the user.

2

MVP workflow

Minimum pages & data to prove it.

3

Nice-to-have

Polish that matters after the core works.

4

Later release

Valuable, but not this class version.

5

Cut line

The boundary that protects the deliverable.

Scope in action

Example: an online store

Basic idea
Product MVP
Later
Sell products online.
Catalog, cart, and a simple checkout (pay on pickup).
Online payments, shipping APIs, multi-vendor, subscriptions.

“Online payments” is the tempting feature. A pay-on-pickup MVP can still prove the idea.

SDGKU FSDITopic 118.2
Examples you’ll recognize

Small, but a complete workflow

Store MVP

Browse the catalog, add to cart, place an order.

Booking MVP

See availability, request a slot, get a confirmation.

Community MVP

Post, comment, browse the feed.

Each includes creation, review, and a reason to return — and nothing more, yet.

Using AI as a design partner, not autopilot

Don’t let generated code justify the scope

Good use

  • Ask AI to estimate implementation risk per feature
  • Ask for a smaller version that still teaches the concept
  • Compare effort, dependencies, and unknowns
?

Ask AI

“What is the smallest version of this feature that still provides user value?”

Talk it through

Discussion prompts

1 What feature would you cut if the demo were tomorrow?
2 What single workflow proves the app idea?
3 What feature sounds easy but needs accounts, APIs, or payment keys?

Draw your cut line

  • Update the project document with the decision and the reason.
